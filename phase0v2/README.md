# ゲーム攻略くん Phase 0 検証ツール v2（Phase0Probe 0.2.0）

Phase 0 で調べる「画面取得」と「入力方式」の実現性を確かめる、小さなコンソールツールです。v1 の実機結果を受けて修正し、テストを2つ追加しました。
**本体（認識・学習・UI）はまだ実装していません。**

> ⚠️ **v2 は Windows 実機で一度も実行していません。** ビルド（Linux 上での win-x64 クロスビルド）と、差分判定・PNG 出力の単体確認までしか行っていません。
> 不具合があれば、画面のエラー表示と `results\` フォルダを送ってください。

## v1 からの変更点

| # | 変更 |
|---|---|
| 1 | キー指定で `Num0`〜`Num9`、`NumPad0`、`テンキー0`、`KP0` を**テンキー**、`D0`、`上段0`、`Top0` を**上段数字**として受け付けます。数字1文字だけを入力すると、どちらか確認します。解釈した結果（VK コード、スキャンコード、拡張キーかどうか）を表示します。**トルネコのキー配置を既定値として内蔵**しました（開く=Num0、閉じる=Num2。メニューの `P` で一覧表示）。 |
| 2 | ① PostMessage はテンキーを正しい VK とスキャンコードで送ります（例: Num0 は VK=0x60、scan=0x52、拡張キーではない）。③ SendInput は **VK で送信**し、送信時の NumLock の状態を記録します。 |
| 3 | ①を **①a（WM_KEYDOWN/UP のみ、先に実施）** と **①b（WM_CHAR も送る）** の両方で自動的に試します。T3/T5/T6 で ① を使うときの送り方は、T2 の結果から自動で決めます（既定はオフ）。 |
| 4 | 差分の判定を改めました。無入力時の揺れを**複数組（既定5組）測って最大値**を使い、さらに**ひとかたまりの大きな変化領域（既定で画面の1.5%以上）**が出たときだけ「変化あり」とします。ダミー窓がキーを受け取ったのにゲーム画面も変わった場合は、**矛盾として警告**を出します。差分画像は、変化した画素を赤、最大の変化領域を緑の枠で示します。 |
| 5 | 最小化中の PrintWindow が極小画像（タイトルバーのみなど）になる場合は、「取得不可」と判定します。 |
| 6 | **新テスト T5「ダンジョン内で①を背面から送って移動」**を追加しました（下記）。 |
| 7 | **新テスト T6「背面で長時間」**を追加しました（下記）。 |
| 8 | T4 は、**自分の印が付いた注入以外はすべてユーザー操作とみなす**モードを既定にしました（リモート操作ツールの入力も含みます）。フックと RawInput は**専用のスレッド**で動かします。全イベントを CSV に記録します。 |
| - | exe を小さくするため、WinForms をやめて素の Win32 API で書き直し、トリミングと圧縮を有効にしました（約17MB。v1 は約75MB）。 |

判定の改良は、v1 の実機画像で確認しました。メニューのウィンドウは最大の変化領域が約5.6%で、変化ありと判定されます。v1 で誤って「受理」になった NPC の移動は 0.7〜0.9% で、変化なしと判定されます。

## 安全面
- ゲームのメモリ読み取り、DLL の注入、ゲームファイルの解析は**一切行いません**。対象ウィンドウは、タイトル・クラス名・プロセス名・位置だけで特定します。
- 各テスト、および T5 の各操作の前に、必ず確認を求めます。
- ③の背面テストでは、テスト用のダミー窓を前面に出してから送ります。送る直前にも前面のウィンドウを確認し、想定と違えば送信を中止します。
- T5 では、道具の使用・投げる・装備などの危険な操作は送りません。決定（Num1）は、メニューの「道具」一覧を開くためだけに使います（カーソルが「道具」にあることを目で確認してから実行してください）。
- フックは入力を見るだけで、止めたり書き換えたりはしません。管理者権限は要求しません。

## 使い方（基本）
1. `bin\Phase0Probe.exe` を任意のフォルダに置きます。署名がないため SmartScreen の警告が出たら、「詳細情報 → 実行」を選んでください。
2. トルネコを**ウィンドウモード**で起動し、ゲーム内のキー配置を次のとおりにしておきます: 上W、左A、下S、右D、決定=Num1、キャンセル=Num2、方向転換=Num5、メニュー=Num0、矢=Num4、斜め補助=Num3、マップ=Num7、足踏み=Num6。**NumLock は ON** にしてください。
3. `Phase0Probe.exe` を起動し、`S` で対象を選びます（一覧の番号、`トルネコ`、`TornekosMysteryDungeon` などで指定できます）。
4. `A` を選ぶと、T1→T2→T3→T5→T6 を順に実行します（テストごとに確認があります）。T4 は `4` で個別に実行します。
5. 入力を求められたら、先にコンソールをクリックしてから入力してください（特に Windows Terminal の場合）。

## 各テストと判定基準

### T1 キャプチャ（前面・背面）
v1 と同じです。WGC と PrintWindow で前面と背面の画面を取り、フレームの届く頻度と黒画面かどうかを記録します。

### T2 入力（①a / ①b / ② / ③ × 前面・背面）
- 手順: 無入力の揺れを5組測る → 開くキー（既定 Num0）を送る → 待つ → 撮影 → 閉じるキー（既定 Num2）を送る → 待つ → 撮影
- **変化あり**の条件: 変化率が「揺れの最大値＋0.2%」を超え、**かつ**最大の変化領域が max(1.5%, 揺れの最大領域×2) 以上であること
- **受理**: 開いた後に変化があり、閉じた後に送信前の画面へ戻ったとき（戻らなければ「要復旧」）
- ①②の判定: ✅ 背面でも受理 / ⚠️ 前面のみ受理 / ❌ どちらも不受理
- ③の判定: ✅ 前面で受理し、背面ではゲームに届かない（ダミー窓が受け取る）

### T3 最小化
最小化中の WGC（最後のフレームで止まるか）と PrintWindow（取得不可か）を記録します。最小化中に①で開くキーを送り、復元後の画面に**大きな変化（メニュー）**が出ていれば、「処理された」と判定します。

### T5 ダンジョン内で①を背面から送って移動（新規）
**準備**: ダンジョン内で、周囲に敵・罠・水路がない広い部屋の中央に立ち、メニューを閉じておきます。ゲームは背面に置きます（コンソールが前面になっていれば十分です）。

1手ずつ「y=実行 / s=スキップ / q=中止」を確認し、各手の前後の PNG と差分画像を保存します。各手の後に、**ゲーム画面で実際に起きたことをメモとして入力できます**（例: 「右上へ1歩」「動かず」「2歩進んだ」）。

| 手 | 内容 | 確かめたいこと |
|---|---|---|
| S01 | 足踏み Num6 | 単発キーで1ターン経過するか（画面の変化は小さいことがある） |
| S02〜S05 | W / S / A / D を1回ずつ | 4方向に1マスずつ動くか |
| S06・S07 | **Num3 を押したまま W+D / S+A を同時押し**（400ms） | 斜め補助キーを押したままの同時押しが、背面の PostMessage で効くか |
| S08・S09 | 補助なしで W+D / S+A を同時押し | 同時押しだけで斜めに動くか |
| S10・S11 | D / A を **1200ms 押しっぱなし**（オートリピート相当の連続送信） | 押しっぱなしで複数マス進むか |
| S12〜S15 | メニュー Num0 → 決定 Num1（道具一覧）→ キャンセル Num2 → キャンセル Num2 | 決定とキャンセルが効くか |

- 判定は ℹ️ 情報です。画面変化の有無に加えて、**移動の向き・歩数は画像とメモで確認**します（カメラがキャラを追うので、移動すると画面全体が変わります）。
- 補足: PostMessage は OS のキー状態を変えません。ゲームが同時押しや長押しを OS のキー状態で判定している場合は、S06〜S11 が効かない可能性があり、それ自体が知りたい結果です。

### T6 背面で長時間（新規）
- ゲームを背面に置いたまま、既定5分間、15秒ごとに①でメニューを開閉し、そのたびに WGC で撮影します。実行時間と間隔は開始時に変更できます。
- 途中でやめるときは、コンソールで `q` を押します。**テスト中はブラウザなど別の作業をして構いません**（ゲームの最小化だけは避けてください）。
- 記録する項目: サイクルごとの fps、開く/閉じるの成否、ゲームが前面だったか、最小化されていたか（`T6_cycles.csv`）、最初のサイクルと失敗したサイクルの画像
- 判定: ✅ 受理率95%以上、閉じるがすべて成功、fps が0になったサイクルなし / ⚠️ 受理率80%以上 / ❌ それ未満

### T4 ユーザー操作の検出（後回し可）
- 既定モードでは、**自分の印が付いた注入以外**（物理入力、リモート操作ツールの注入など）を検知するとループが止まります。開始時に「物理デバイスのみ」へ切り替えることもできます。
- 校正では、自分の注入をフックと RawInput の両方で正しく分類できたかを確認します。v1 で起きた取りこぼしが、専用スレッド化で直ったかもここで確かめます。全イベントは `T4_input_events.csv` に保存します。

## 出力と返し方
`results\yyyyMMdd-HHmmss\` に `report.md`、`report.json`、PNG、CSV（T4/T6）を出力します。**このフォルダを丸ごと zip にして送ってください。**
PNG が多い場合は、`report.md`、`report.json`、`*.csv` と、`T5_*_diff.png`・`*_2after*.png` だけでも分析できます。

## 既知の制約・未検証の点
- **Windows 実機では未実行です。** 素の Win32 ウィンドウ（ダミー窓・メッセージスレッド）、トリミング後の WinRT（WGC）の動作、専用スレッドでのフックは、実機で初めて確認することになります。
- ② は ViGEmBus が入っていなければスキップします。ViGEm のネイティブ DLL を展開する処理は、単一 exe の中では未確認です。
- NumLock の状態は参考値です（ツールのスレッドから見た値のため）。
- T5 の移動方向は自動では判定しません。画像とメモで確認してください。
- 対象ゲームが管理者権限で動いている場合、①③は遮断されます。
