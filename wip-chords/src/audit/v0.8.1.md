## 主な変更（v0.8.0 → v0.8.1）

- 互換性テストの記録の不具合: 受理されなかった回を "rejected"（compat_test_steps の CHECK の外）で書いていたため、不合格のテストは記録ごと失われ、DB にもログにも残らなかった（v0.7.0 の 09:50 の「使える入力方式がありません」の原因が追えなかった）。accepted / ignored / not_reverted に直し、結果をログ（compat_test）にも残す
- 画面に出た注意・エラーをログ（notice）にも残す（診断 zip だけで確認するため）
- 予測の外れの境界: surprisal は上限（未知の組 = log2(状態数+1)）付近に偏るため、平均＋2.5σ が上限を超えて境界が出なかった（v0.8.0 の実行 #21 の 334 手で 0 回）。直前 5 手の平均との差（文脈に対する跳ね上がり）で外れ値を判定する
- 健全性レポート: 判定は今回の起動のログだけで行い、前回までは「情報」に（v0.7.0 時代の中断で総合が「注意」になっていた）。連続履歴の件数を「手数 − 打ち切りの手」と照合。パターンの種類別の件数、今回の実行の新しいパターン数・境界の候補の内訳、待ち時間の推移、互換性テストの結果を追加

## 実機データ

- 実機データを見たか: **はい（診断 zip のみ）**。健全性レポート・DB の件数・ログのイベントの件数と、ターン判定の待ち時間の推移、系列の境界の理由の件数、surprisal の値の分布（最小・最大・平均・標準偏差）を確認した。画像は zip に無い。プレイの内容（どの画面・どの操作か）は見ていない
- 注記: 予測の外れの修正の確認のため、診断 zip の履歴に対して旧方式と新方式（文脈の長さ 3・5・10）の境界の件数を計算した。文脈の長さ 5 は汎用の既定（短い文脈）として先に決めていた値で、件数を見て選んだものではない。合格の判定は合成データのテスト（Prediction_error_boundaries_fire_even_when_most_steps_are_unpredictable）で行う

## 疑わしいもの・判断の記録

- 「変化なし」の待ち時間は 600ms と約 1.2s を行き来する（調整 16 回のうち大きな変化 3 回）。判定が早すぎた手は 2/335（0.6%）で、不具合ではないと判断し変更しない（揺れを抑える仕組みは提案に回す）
- 停止で打ち切った手は連続履歴に入れない（結果の画面が無いため）。件数の照合はこれを前提にする
