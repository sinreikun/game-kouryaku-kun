# 内発的な価値と自己生成の目的の設計（t33u 7〜9。v0.16.0 で安全な部分を実装）

## 前提
- 目的は開発者が与えない。ゲームの意味（勝つ・進む・HP・敵など）は使わない。
- 目的も価値も、既存の構造（内部モデルの関係・探索の統計・入力なしの基準・連続履歴）から作る。新しい知覚も意味ラベルも足さない。
- 「数が多いほど良い」量（画面の数・変化の数・発見の数・手数・達成の数）は価値にしない。成長の計器・グラフ（表示用）は読まない。
- 計画を先に作らない。目的を追うのに要る最小の道筋（知っている関係の最短経路）だけ。

## 流れ
経験 → 仮説（内部モデルの関係とその不確かさ） → 目的の候補 → 選択 → 何手かかけて追う → 達成／失敗／放棄 → 価値の更新

| 段 | v0.16.0 の実装 |
|---|---|
| 目的の候補 | reach: 未試行の操作が残る、または操作の結果の不確かさが 0.5 以上の知っている画面へ行く（v0.19.0 で後者を追加）／retest: 今の画面の揺らいでいる関係（不確かさ > 0.5、直接の観測 2 回以上）を確かめ直す |
| 選択 | 種類の価値 × 相手の不確かさ（reach は道筋の長さで割る）に比例。全体として選ぶかどうかも価値の平均で決める（低ければ探索に任せる） |
| 追う | 道筋の手を順に送る（Rule = goal）。外れたら 1 回だけ引き直し、だめなら放棄。手数の上限は道筋 + 2 |
| 終わり | reach: 相手の画面に着いたら達成。retest: 予測どおりなら達成、違えば失敗（どちらも観測） |
| 価値の更新 | 終わりから 3 手後に、相手の不確かさがどれだけ減ったか（学習の進み）を測り、種類の価値の移動平均に入れる |

## 悪用の防止
| 悪用 | 防ぎ方 |
|---|---|
| ノイズ追い（予測できない所を「不確かだから」と追い続ける） | 価値は不確かさそのものではなく「減った量」。減らなかった相手は休み（20 手から倍々、最大 1280 手） |
| 入力なしでも起きる変化を自分の成果とみなす | 道筋・確かめ直しの相手に、操作の関与（v0.15.0 の推定）が 0.3 未満の関係を使わない |
| 知っている所に留まる | 進みのない相手は休む。目的の手は直近 100 手の 3 割まで（探索が主） |
| 待つ手の連打 | 待つ手は道筋にも確かめ直しの相手にも入れない |
| 達成の数を稼ぐ | 達成の数は価値にも健全性の良し悪しにも使わない |

## 記録（出どころ）
- goal_events（DB v11）: 目的ごとに達成・失敗・放棄と、学習の進みの測定（reviewed）。origin に根拠の関係と観測の回数。
- 判断の記録の rule = 'goal'。人間の手（rule = 'human'）は目的を中断する（切替ごとに放棄）。

## 簡単な計画（v0.19.0）
- 道筋を探すとき、選択の候補に入っている操作の並び（スキル）も、その始まりの画面からの 1 本の道として使う（結果は並びとして直接観測した関係・確率 0.5 以上）。休止中の並びは使わない。
- 並びの中の手数は道筋の長さに数えない。4 手以上の道筋も「スキル＋手」で表せる（並びそのものは 2〜3 手のまま）。
- スキルを含む道筋の達成からは、新しい並びの候補を作らない（入れ子の並びはまだ作らない）。

## まだ作らないもの（t33u 9）
- スキル（目的を達した手の並びの再利用）: 操作の並び（ActionSequence）と目的の結果を結ぶ。目的の達成が 2 回以上同じ道筋で起きたら候補にする予定。
- 計画（複数の目的の組み合わせ・先読み）: 目的の価値が安定してから。
- 目的の種類を経験から増やすこと（例: 入力なしの遷移の先へ行く）。
