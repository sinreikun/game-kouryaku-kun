## 0. 全体像

```
Raw Frame（取り込み 1466×825 など・WGC/PrintWindow）
 └ Global Scene（画面の種類 m*・配置・見た目の状態 v*・前景の鍵）
 └ Regions（16×12 画素の区画の変化・因果の分類・領域の追跡）
 └ Local Pattern / Entity 候補（32×24 細かい格子のつながり・追跡 ID・再同定）
    └ Entity State（appearance_state A/B/C…・移動量・出現/消失・継続時間）
    └ Relations（候補の組の差・距離・接近/離反・重なり・隣接・同じ動き）
 └ Text / Numeric（OCR の行・位置・確信度・状態 observed/inherited・数字の系列）
 └ Temporal（静止までの時間・自然な変化・遅れて来た変化）
 └ Provenance（agent / human / wait・schema 版）
 = Structured Observation（1 手に 1 つ。DB structured_observations）
     ├→ World Model: (State ID + Action → Next State) と (Structured Obs + Action → Predicted Changes)
     ├→ Prediction Error（層ごと）→ 仮説・再観測・分化（試算 → 取り消しのある分割）
     ├→ Feature Importance（予測に効く特徴を経験から）
     ├→ Action Selection（不確かさ・情報の値打ち・能動的な実験）
     ├→ Goal / Planning（局所の目的・構造化した条件）
     └→ Skill（観測条件 → 予測できる結果）
```

## 1. 最上位原則（仕様 §1）
- 画面から人間が観測できる情報はすべて使ってよい。使わない: 内部値・メモリ・API・開発者の意味付け。
- 守り方: (1) 観測の種類名は形式的（`entity_moved` など）。(2) 数値の既定値には `// 根拠:` を付け、`ConstraintAuditTests` が検査する。(3) 各版の監査記録 `audit/vX.md` 9 項目。
- 状態: **実装**（ConstraintAuditTests・audit/）。差: なし。

## 2. 1 Action = 1 Complete Observation（仕様 §2・§25）
- 設計: 手 → 静止の判定 → 観測の全層を作る（OCR を含む）→ 次の手。OCR は毎手。読まない理由は 3 つだけ: `reuse`（区画のハッシュがすべて同じ＝前の行を継承）・`cache`（同じ見た目を読んだことがある）・`region`（変わった区画に掛かる行だけ読み直し、他は継承）。
- 「再 OCR していない」と「観測していない」の区別: 行ごとに `status = observed | inherited`、層ごとに `observed | inherited | not_observed | not_implemented`。
- 区画の変化はノイズに強い判定（`CellStabilizer`：既存の画素のしきい値 24 を超えた点があるときだけ変わった）。一部読み直しで画素の変わらない行は前の読みを使う（`TextReader.KeepUnchanged`）。
- 状態: **実装**。コード: `Session.ReadTextEachStep`（同期化）・`TextReader.Plan/ReadAsync/KeepUnchanged`・`CellStabilizer`。実機 #118: 観測 550/550・文字の層の未観測 0。
- 差: 並列化（OCR とエンティティの層の並行）は未。1 手の時間は v0.28.2 比 +0.3〜0.6 秒。
- 予定: P-7（性能）で OCR と細かい格子の計算を並行にする（観測の完全さは変えない）。

## 3. 階層（仕様 §3・§4）
### 3.1 Structured Observation の形（schema 1・JSON は snake_case）
| 層 | 欄 | 状態の意味 |
|---|---|---|
| 共通 | `schema`・`step`・`provenance`(agent/human/wait)・`action`・`before`・`after` | — |
| `global` | `node`・`mode`・`layout`・`visual_state`・`fg_text_layout`・`status` | 大域の索引。世界状態そのものではない |
| `regions` | `status`・`changed_cells`・`regions[]`(track・bbox・cells・causality・natural_rate・new_track) | 16×12 |
| `text` | `status`・`read_kind`(full/region/reuse/cache/none)・`diff_kind`・`lines[]`(text・box・confidence・cell・status・change)・`numbers[]`(value・previous・series)・`observed`・`inherited`・`action_caused` | 行ごとに observed/inherited |
| `temporal` | `boundary_ms`・`changed`・`natural_change`・`status` | — |
| `entity_layer` | `status`・`candidates[]`(id・track・bbox・cx・cy・cells・appearance・appearance_state・dx・dy・moved・appearance_changed・new・confidence・age)・`disappeared[]`・`relations[]` | 32×24 |
| `prediction` | `status`・`p[6]`・`occurred[]`・`surprise[6]`・`predicted_move`・`world_next`・`world_p`・`world_hit` | 手の前に出した予測と外れ |
| 計算欄 | `entities`・`relations`・`appearance` | 層がなければ `not_implemented` |
- 版の規則: 欄の追加だけなら schema は同じ（旧い JSON はそのまま読める）。意味の変わる変更・欄の削除は schema を上げ、`schema_meta.observation_schema` と行ごとの `schema_version` で区別する。
- 状態: **実装**（`Core/Observation/StructuredObservation.cs`・`LocalPatterns.cs`）。
- 差: 最終構造で足すもの（予定の欄、すべて追加）: `entity_layer.candidates[].duration_steps`（継続時間）・`texture`（局所の形の符号）、`temporal.delayed[]`（遅れて来た変化）、`temporal.window`（リアルタイム用）、`importance`（特徴の重要度の参照）。schema は 1 のまま追加する。
### 3.2 Global Scene（§4）
- 既存の `ScreenModeBook`（色分布）・配置・`VisualStateBook`（遷移で分けた見た目の状態）・`ForegroundStates` を `global` に集める。同じ Global Scene でも局所の層が違うことを観測に残す（試験 `Same_global_scene_with_different_local_state_stays_distinct…`）。
- 状態: **実装**。

## 4. Region（仕様 §5）
- 現状: 16×12 区画の画素の変化 → つながり → IoU で追跡（`ObservationBuilder.Regions`）。区画ごとの因果の分類（`RegionCausality`：action/independent/unknown、ベイズ因子）。
- 仕様の基準のうち: 周囲との差（**部分**：候補の背景＝まわりの枠の最頻色）・時間的な共変動（**未**）・一緒に動く（**部分**：関係の `same_move`）・Action との相関（**実装**：RegionCausality）・繰り返しの出現（**部分**：再同定）・時間の性質の違い（**部分**：自然な変化の率）。
- 設計（最終）: Region 候補 = 「同じ手の後に一緒に変わる区画の群」。区画の組ごとの共変動（両方変わった回数の割合・Jeffreys）を数え、強く共変動する区画をつなぐ（ベイズ因子 ≥ ln10。新しい定数なし）。手ごとの共変動と入力なしの共変動を分け、Region に「手で動く群」「自然に動く群」の性質を持たせる。
- 予定: P-4。受け入れ: 合成で「2 つの離れた区画が同じ手でいつも一緒に変わる」→ 1 つの Region、「入力なしで周期的に変わる背景」→ 自然の群。

## 5. Entity 候補・追跡・再同定（仕様 §6）
- 現状: `FineGrid`（32×24・ノイズに強いハッシュ）→ 変化のつながり → 背景（枠の最頻色）でない・同じ色の符号の区画へ広げる → 候補。追跡は前の位置に変化があった追跡だけを対象に、位置と色分布の差で互いにいちばん近い組（固定の距離なし）。消えた追跡は見た目が完全に同じなら再同定。大きさが変わって重なるなら移動としない。
- 状態: **実装**（`EntityTracker`）。実機 #111: 全画面の候補 1.3%（#110 は 65%）。
- 差: (a) 動かない物は候補にならない（変化した所からしか候補を作らない）。(b) 継続時間・追跡の確信度の時系列は部分。(c) 形・テクスチャの特徴は色の 4×4 だけ。
- 設計（最終）: 「繰り返し観測される局所パターン」の記憶（見た目のハッシュ → 出た位置の集合・回数）を持ち、静止していても一度変化で見つかった見た目は、毎手その位置を確かめる（確かめるのは記憶にある見た目だけ＝ROI。全画面の探索はしない）。
- 予定: P-5。受け入れ: 合成で「動いた後に止まった四角」が止まっている間も同じ追跡 ID で存在し続ける。

## 6. 見た目の状態（姿勢・向き）（仕様 §7）
- 現状: 外接矩形の色の符号を 4×4 にそろえたハッシュ → 追跡ごとに A,B,C…。位置が同じで見た目だけの変化を数える（`appearance_only`）。
- 状態: **実装**（試験 `Appearance_only_change_gets_distinct_states_and_returns_to_the_first`）。
- 差: 見た目の状態と手・移動の方向・関係の相関は記録の中にあるが、表（appearance_state × action → 次の appearance / 移動方向）がない。
- 予定: P-6（ブロック 13 特徴の重要度と同時）。受け入れ: 合成で「手 x の後は見た目 B、手 y の後は C」を表から予測できる。

## 7. Relation（仕様 §8）
- 現状: 組ごとの dx・dy・距離・`approach/recede/same/new`・重なり・隣接・同じ動き。
- 状態: **実装**（記録）。差: 追従（一方の動きの後にもう一方が同じ向きに動く。時間の遅れつき）・出現消失の時間関係は**未**。
- 予定: P-6。受け入れ: 合成で「A が動いた次の手に B が同じ向きに動く」を追従として記録。

## 8. OCR・文字・数字（仕様 §9・§10）
- 現状: 行（文字・位置・確信度・区画・observed/inherited・変化の種類）。数字は行と位置で系列（`NumberObs.series`）。文字の変化は `observed` と、区画ごとの入力なしの率・手が起こした割合・確信度（`TextChangeBook`・`RegionCausality`）に分けて持つ。自然に変わる文字も消さない。
- 状態: **実装**。差: 数字の系列と他の層（候補の出現・関係・遷移）との相関は**未**（ブロック 13 で）。
- 予定: P-6。受け入れ: 合成で「手 x の後に数字が 4 ずつ減る」系列を予測できる（減る量の予測）。

## 9. 自然な変化と手の後の変化（仕様 §10・§12・§18）
- 現状: 画面・遷移・画素の区画・文字の区画・局所の出来事（`LocalEventModel.Causality`）を、待つ手（入力なし）と手の後に分けて数える。マスクで消さない（安定判定用の `IdleMask` と World Model 用の観測は分離済み）。
- 待つ手の値打ち（`WaitInformation`）: 画面・遷移・画素・文字の 4 成分。**部分**: 局所の出来事（移動・見た目・出現・消失）の成分がない。
- 予定: P-2 で `WaitInformation` に局所の出来事の成分を足す（同じ 1 − Π の合わせ方）。受け入れ: 合成で「入力なしで点滅する候補」の待つ手の値打ちが観測とともに下がる。

## 10. Temporal（仕様 §11）
- 現状: 静止までの時間・変化の有無・自然な変化の率・遅れて来た変化（`late_change` ログ）・周期（`TemporalBook` の性質）。**部分**: 遅れて来た変化が構造化した観測に入っていない。
- 予定: P-7。受け入れ: 合成で「手の 1 秒後に変わる区画」が `temporal.delayed` に記録される。

## 11. 状態の表現（仕様 §13）
- 現状: State ID（`m|配置#v`）は索引。構造化した観測は DB に全部ある。World Model（`TransitionModel`）は State ID のみ、局所の予測（`LocalEventModel`）は State ID × 手の上の出来事。
- 状態: **部分**。
- 設計（最終）: 「局所の文脈」＝ State ID に加えて、予測に効くと分かった構造化した特徴（ブロック 13 の結果）だけを鍵に足す。足すのは試算で外れが減ると確かめた特徴だけ（§13）。

## 12. World Model（仕様 §14）
- 現状: `TransitionModel`（Dirichlet・修正・弱い事前）＋ `LocalEventModel`（出来事 6 種の確率と移動量）。両者の予測を手ごとに並べる（`prediction.world_*`）。
- 状態: **部分**（条件 8）。差: 局所の予測が構造化した特徴（位置・見た目・数字）を条件にしていない。
- 設計（最終）: 予測 = P(出来事 | State ID, 手, 局所の文脈)。局所の文脈は §13 で選ばれた特徴。次の State の予測は既存のまま。
- 予定: P-3。受け入れ: 合成で「同じ Global Scene・同じ手でも、候補の位置で移動するかが決まる」とき、文脈つきの予測の驚きが文脈なしより下がる（1 つ抜き）。

## 13. 予測の外れ（仕様 §15）と再分類
- 現状: 層ごとの驚き（`LocalEventModel.Observe`）・外れが続く組（平均の驚き > ln2）・World Model とのつき合わせ（`CoarseStateEvidence`）・位置で分けたときの試算（ベイズ因子・1 つ抜きの驚き。**分けない**）。外れが続く出来事は能動的な実験の値打ちから外す。
- 外れの分類（最終）:
  | 種類 | 見分け方 | つなぐ先 |
  |---|---|---|
  | 状態の粗さ | 次の画面は当たる・局所は外れる・文脈で分けると外れが減る | 局所の文脈の追加（P-3） |
  | Entity の同定の誤り | 追跡の確信度が低い手に外れが集まる | 追跡の再計算・再観測 |
  | 隠れた条件 | 文脈で分けても減らない・履歴（前の手の出来事）で減る | 履歴の特徴を候補に（P-3） |
  | 自然な変化の取り違え | 待つ手でも同じ率で起きる | 自然の側へ（既存の RegionCausality） |
  | 観測の不足 | 観測が少ない | 能動的な実験（既存） |
- 状態: **部分**（条件 10: 試算までで、学習・再分類へ戻っていない）。
- 予定: P-3。受け入れ: 上の 5 種を合成で作り分け、それぞれ正しい先へつながる。

## 14. 特徴の重要度（仕様 §16）
- 現状: **未**（ScoreBreakdown が項ごとの短期・長期の寄与を記録するだけ）。
- 設計: 特徴 f（候補の位置の区画・見た目の状態・数字の増減・文字の区画の変化・関係の種類…）ごとに、「f を知ると次の出来事・次の State の予測の驚きがどれだけ下がるか」（1 つ抜きの対数損失の差）を数える。下がらない特徴は観測から消さず、手の値打ち（文字の項・不確かさ）への寄与だけを下げる。開発者は重要度を決めない。
- 予定: P-3 と同じブロック（予測の文脈の選び方そのもの）。受け入れ: 合成で「予測に効く特徴」と「よく変わるが効かない特徴」を混ぜ、前者だけが重要になる。

## 15. 短期の変化と長期の進み（仕様 §17）
- 現状: `FrontierRegions`（地域の進みの減り・戻り）・`ScoreBreakdown.Outcome`（新しい辺・新しい画面への寄与）。**部分**: 寄与の記録が再訪の価値に戻っていない（地域の減りは戻っている）。
- 予定: P-8。受け入れ: 合成で「見た目・文字はよく変わるが新しい遷移の増えない領域」の再訪の値打ちが下がり、後で新しい関係が見つかると戻る。

## 16. Wait（仕様 §18）
- §9 参照。**部分**（局所の成分なし）。予定 P-2。

## 17. Action Selection（仕様 §19）
- 現状: 不確かさの項 = 1 − (1 − 画面の不確かさ・文字)(1 − 局所の情報の量)（`Session.WithLocal`）。学べない出来事は外す。待つ手は入力なしの基準の不確かさ。
- 状態: **部分**（条件 11 は満たす。「どの手なら今の仮説を最もよく区別できるか」の能動的な実験は未）。
- 設計（最終）: 仮説（§13 の分割の候補・文脈の候補）ごとに、手 a の結果の予測が仮説の間でどれだけ違うか（予測分布の差＝期待される情報の量）を値打ちにする。新しい重みは置かず、既存の不確かさの項に同じ合わせ方で入れる。
- 予定: P-9。受け入れ: 合成で、2 つの仮説を区別できる手が、区別できない手より選ばれる。

## 18. Goal / Planning（仕様 §20）
- 現状: Reach・Retest の目的。v0.29.6 で不確かさに局所の予測を入れた（`SelfGoals.U`・`NodeUnc`）。**部分**: 目的の種類が State ID のまま（局所の出来事の再現・Relation の確認・数字の変化の条件の確認は未）。
- 設計: 目的の種類「出来事の確かめ（画面, 手, 出来事）」を足す。進み = その出来事の不確かさの減り（既存の Review と同じ）。計画は既存の道筋（State ID）で行き、着いたら手を打つ。
- 予定: P-10。受け入れ: 合成で、外れが続く出来事の確かめが目的になり、進みが測られる。

## 19. Skill（仕様 §21）
- 現状: 操作の並び（`ActionSequenceMiner`）と並びの局所の効果（`SkillLocalEffects`、記録）。**部分**（条件 13: 条件として使えない）。
- 設計: Skill = （開始条件: Global Scene ＋ 局所の文脈）→（手の並び）→（終了条件: 予測できる出来事）。効果が確かな（Jeffreys > 0.5・6 回以上）並びだけ。しきい値は緩めない。
- 予定: P-11。受け入れ: 合成で「位置 A のときだけ効く並び」が、位置 A を開始条件として持つ。

## 20. Human Control（仕様 §22）
- 現状: 同じ構造化した観測を `provenance=human` で作り保存する。模倣はしない。
- 状態: **実装**。

## 21. Viewer（仕様 §23）
- 現状: 1 手サマリー（なぜこの手か・点数の内訳）。構造化した観測の表示・重ね表示は**未**（条件 14）。
- 設計: ライブ画面の上に、細かい格子の候補の矩形と追跡 ID・見た目の状態・移動の矢印・Region（因果の分類で色分け）・OCR の行（observed/inherited で線の種類）を重ねる。1 手サマリーに予測（出来事の確率）と外れ・World Model の予測・目的・Skill を表で出す。人間が意味を教える入力欄は作らない。
- 予定: **P-1（次に実装）**。受け入れ: (a) 表示が構造化した観測の JSON だけから作られる（試験で JSON → 描画の要素を検査）。(b) 実機で人間が候補・追跡・見た目の状態・文字の継承を目で監査できる（§30 の評価用）。

## 22. Health Report（仕様 §24）
