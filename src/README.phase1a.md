# ゲーム攻略くん Phase 1: バックエンド基盤（確認用ハーネス付き）

設計書 v2 の Phase 1 で最初に作る部品「バックエンド基盤」です。画面の取得、入力の送信、ユーザー操作の検出、ターン検出の土台、Game Profile の読込を、ゲームに依存しない共通部品として実装しました。
動作確認には、同梱のコンソールハーネス `GameKouryakuKunHarness.exe` を使います。WPF の画面（鑑賞UI・バックエンド状態パネル）、セットアップマネージャ、OCR は、この後の Phase 1 の作業で作ります。

## 同梱物

```
GameKouryakuKun-Phase1/
├─ GameKouryakuKunHarness.exe        確認用ハーネス（win-x64 単一exe・自己完結。.NET のインストールは不要）
├─ profiles/torneko-remaster/profile.json   トルネコ用 Game Profile（編集できます）
├─ README.md                          このファイル
└─ source/                            ソース一式（下記「構成」）
```

## 実機で確認してほしい手順

1. ゲームを**ウィンドウモード**で起動し、ダンジョン内で自由に動ける状態にします（メニューは閉じておきます）。キー設定は Phase 0 と同じにしてください（上W 左A 下S 右D、決定 Num1、キャンセル Num2、斜め補助 Num3、矢 Num4、方向転換 Num5、足踏み Num6、マップ Num7、メニュー Num0）。
2. zip を展開し、`GameKouryakuKunHarness.exe` をダブルクリックします（PowerShell から引数付きで起動しても構いません）。
3. ハーネスは次の順に進みます。

   | 段階 | 内容 | あなたの操作 |
   |---|---|---|
   | Profile・ウィンドウ特定 | プロセス名 `TornekosMysteryDungeon-Win64-Shipping` とクラス名 `UnrealWindow` でゲームを探す | 複数見つかったときだけ番号を選ぶ |
   | 1. 取得プローブ | WGC と PrintWindow でそれぞれ1.5秒取得し、fps・コピー時間・黒画面かどうかを測る | なし |
   | 準備確認 | 「ダンジョン内で操作できる状態」になっているかを確認 | コンソールをクリックして Enter |
   | 2. ノイズ較正 | 入力を送らずに1.5秒観測し、待機アニメの領域と残留ノイズを測る | 触らない |
   | 3. 互換性テスト | 前面役ウィンドウを前面に出し、ゲームを背面にしたまま「メニューを開く→閉じる」を3回送る | 触らない |
   | 移動の確認 | ランダム操作に移動と足踏みを含めるか聞かれる | `y` で移動あり、Enter のみでメニュー開閉だけ |
   | 4a. 停止機能の確認 | ①最小化→元に戻す ②ゲームを前面にしてキー（Shift等）→5秒触らない ③Ctrl+Shift+F9 を、案内に従って順に確認（各30秒、`s` でスキップ、`--no-checks` で省略） | 案内どおりに操作し、最後にゲームを元の状態に戻して Enter |
| 4. ランダム操作 | 安全な操作をランダムに30回送り、1手ごとに「変化開始・静止開始・境界」の時刻を表示する | 普段どおり別のアプリを使って構いません |

4. 終わったら、`results\<日時>\` フォルダを zip にして送ってください。中身は次のとおりです。
   - `summary.md`: 集計
   - `harness.log.jsonl`: 全イベント
   - `*.png`: 最初の2手と、異常（変化なし・時間切れ）が出た手の前後画像

### 追加で試してほしいこと（できる範囲で）

| 確認したいこと | 手順 | 期待される結果 |
|---|---|---|
| 背面で作業しても止まらない | ランダム操作中に、ブラウザでの文字入力や動画の再生を続ける | 一時停止しない（ログの「分離中のため無視」が増える） |
| ユーザーがゲームを触ると止まる | ランダム操作中にゲームをクリックして前面にし、キーを押す | `[一時停止] ユーザー操作` が出て、5秒間何も操作しなければ再開する |
| 最小化で止まる | ランダム操作中にゲームを最小化し、10秒後に元に戻す | `[一時停止] ゲームの最小化` が出て入力が止まり、元に戻すと自動で再開する |
| 緊急停止 | `Ctrl+Shift+F9`（どのアプリが前面でも有効） | すぐに停止し、集計を書いて終了する |
| 移動の1歩判定 | 移動ありで実行し、ゲーム画面を見る | 縦横・斜めとも1回の入力で1歩だけ動く（80ms の短押し・リピートなし） |

### 設計書との対応と Phase 0 の知見の反映

| 部品 | 実装内容 |
|---|---|
| ICaptureBackend（§2.1.5） | 主は WGC、予備は PrintWindow（PW_RENDERFULLCONTENT）。どちらもウィンドウ単位で取得し、デスクトップは取らない。CaptureSupervisor が150msごとにウィンドウを監視し、**最小化・クローク・消失を検知すると一時停止を要求**する。元に戻したらフレームが再開したかを確かめ、来なければ再起動し、それでも駄目なら予備に切り替える |
| IInputBackend（§2.10.6） | **既定は PostMessage（WM_KEYDOWN/UP だけ、WM_CHAR なし）で、分離等級は isolated**。lParam には正しいスキャンコード・拡張ビット・前回状態・遷移ビットを入れる（テンキーは VK 0x60〜0x69、スキャンコード 0x52 0x4F 0x50 0x51 0x4B 0x4C 0x4D 0x47 0x48 0x49、非拡張）。**1手は 80ms の短押しで、リピートは送らない**（Phase 0 で400msの押下だと1〜2歩とばらついたため）。同時押しは15ms間隔で押し、逆順に離す。押しっぱなし（Hold）は明示したときだけリピートを送る。SendInput は前面専用で、同意がなければ無効。各キーを押す直前に前面がゲームかを確認する |
| 禁止キー | 常に禁止: Windowsキー、Alt+F4、Alt+Tab、Ctrl+Esc、Alt+Enter、Shift+Tab など。Profile の forbidden_keys / forbidden_combos（トルネコ: Esc、F12、Alt、Tab ほか）も加わる。禁止キーは Profile に割り当てられない |
| Backend Probe・互換性テスト（§2.13） | 往復操作（メニューを開く→閉じる）を状態B（ゲーム背面）で既定3回送り、受理（変化の有無）、復帰（元に戻ったか）、遅延 p50/p95 を記録する。背面で合格した方式を分離等級の高い順に推薦し、前面でしか合格しない方式は同意がないと選ばない。往復操作の定義はハーネス側に置き、Profile には書かない |
| UserActivityMonitor | **RawInput のみで判定し、フックは使わない**（Phase 0 でフックは自分の注入を取りこぼした）。既定は AllButOwn で、自分の印付き注入以外（リモートデスクトップ越しを含む）はすべてユーザー操作とみなす。止める方針: 分離等級が isolated のときは**ゲームが前面のときだけ**止める（ユーザーが別アプリで作業していても止めない）。SendInput 使用中は常に止める。再開は最後の操作から5秒後 |
| ターン検出の土台（§2.3） | 状態は Idle → InputSent → Changing → Settling → 境界（Normal / NoChange / Timeout / Aborted）と進む。判定は**変化率と最大連結領域の両方**で行う（NPC の動きのような散らばった小さな変化は無視）。待機アニメはノイズ較正で自動的にマスクする。静止判定は静止開始時のフレームと比べるので、ゆっくりしたフェードも取りこぼさない。WGC は画面が変わらないとフレームを送らないため、フレームが来ない時間も静止として扱う |
| 画面固定の半透明UI | `FixedOverlayTracker` を実装した。画面全体がスクロールした差分のうち、位置が変わらなかった領域を「画面固定UI候補」として記録する（Phase 0 で見えた青い半透明の四角やステータス表示）。意味は付けない。Phase 2 以降で、スクロール量の推定やタイル照合からこの領域を除外するために使う |
| Game Profile（§9） | JSON（コメント可）を厳格に検証する。**書けるのは window（プロセス名・クラス名・タイトル）と input（キー割当・既定押下時間・禁止キー）だけ**で、未知のキーはエラーになる。label は40文字までに制限し、説明文を書けないようにした。同じ物理キーの重複割当、あいまいな数字（例 `"1"`）、禁止キーの割当もエラーになる |

## 安全設計（ゲームへの干渉をしない）

- **禁止API検査**（ユニットテスト `ForbiddenApiTests`）は3つの検査からなります。
  1. ソース全体に、メモリ読取・プロセスハンドル取得・注入・フック・キー状態のポーリング・ゲームファイルやレジストリへのアクセスにあたる語が無いこと
  2. P/Invoke 宣言が `Native.cs` の1か所だけであること
  3. **ビルド済みの全DLLのメタデータ**を読み、すべての P/Invoke が許可リストに入っていること。あわせて `Process.Handle`、`MainModule`、`Modules`、`GetProcessById`、`ProcessModule`、`Registry` などを参照していないこと
- ゲームウィンドウの特定に使うのは、ウィンドウのタイトル・クラス名と、OS のプロセス一覧にある実行ファイル名だけです。プロセスは開きません。
- 入力は PostMessage でゲームのウィンドウだけに送るので、ユーザーのキーボード・マウス・前面アプリには影響しません。マウス操作は一切送りません。
- ユーザー操作の検出では、キーの内容（どのキーか）を記録しません。記録するのは種類（キー／マウス）と出所（物理／他の注入）だけです。

## まだできていないこと・未検証のこと

- 実機での動作はまだ確認していません（このハーネスがその確認用です）。
- 未実装（Phase 1 の残り）: WPF の画面とバックエンド状態パネル、配置管理（画面外への退避など）、セットアップマネージャ、OCR、`app.sqlite`、仮想パッド（②）Backend、§10.3 の分離受け入れ試験（10分間の並行作業）の自動化。
- ターン検出の既定値は 変化なし判定 1200ms（初回の実機結果で 900ms から延長）、安定 250ms、上限 8000ms です。安定時間は「境界後の変化」の実測回数を見て調整します。
- 「変化なし」でも画素の局所的な小変化があった場合は「局所的な小変化あり」と注記します（実機で、足踏み中に敵が1体だけ動いたターンが「変化なし」と判定されたため。敵の移動と待機アニメの区別は Phase 2 の画面理解で行います）。
- 「変化なし」が4回続くと、ランダム操作を中止します（ゲームオーバー画面などで空打ちを続けないため。`--max-nochange-run`）。
